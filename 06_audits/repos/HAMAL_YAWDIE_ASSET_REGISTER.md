## Add or refresh an asset

1. Search known repos for HAMAL, YAWDIE, Yadi, Yawds, and relevant asset names. Record which sources were searched and which still need access or verification.
2. For each reusable skill, plugin, MCP, workflow, or API, record its purpose, owner, source path and commit or provider version, visibility, license or reuse authority, destination, and verification status. Include the use case, expected output, and required permissions.
3. Mirror reusable public files when appropriate. Link public vendor packages and API documentation with pinned versions where available. Keep private code and documentation in the approved private workspace and register access there. Keep keys, tokens, private endpoints, and live runtime state in their approved systems.
4. Compare source and destination before updating. Record any intentional link changes and scope the commit to reviewed files. Report installation, tool access, and execution separately with evidence.
