# YAWDIE’s HAMAL operating brief

Start in HAMAL MOB PLAYBOOKS for doctrine, reusable skills, workflows, and the [asset register](../06_audits/repos/HAMAL_YAWDIE_ASSET_REGISTER.md). HAMAL brings together Hanzo, AMA (Art Mob AGInts), and Lux. The AMA Command Center remains the home of the local YAWDIE worker and its queue. Mobstack runs approved workflows. Each workload repo owns its implementation and release evidence.

## Set up on the Mac

In Terminal, run this from your usual development parent folder if a checkout does not already exist.

```sh
git clone https://github.com/MajorDream444/HAMAL_MOB_PLAYBOOKS.git
cd HAMAL_MOB_PLAYBOOKS
git rev-parse HEAD
```

For an existing checkout, check `git status` and the origin first. Fetch and fast-forward only when safe. Open the folder as a Codex project. Ask YAWDIE to read this brief and the register, then verify the files and permissions it can actually use.

- Read the [Venture Discovery skill](../.agents/skills/mobstack-venture-discovery/SKILL.md) and the [six-document build handoff](../02_playbooks/mobstack/build-handoff/README.md).

- Run a read-only HAMAL Music Engine discovery pass when requested. Compare contract clarity, royalty tracking, and organizing claim records. Separate public evidence, simulated buyer objections, and questions for real artists. Return a decision brief before drafting build scope.
- Report checkout path and commit, files loaded, capabilities verified, any local runtime or queue receipt actually observed, gaps, and the next owner. Keep private reports and records in their authorized locations.

For paid or exclusive offers, include the [commerce release checks](../02_playbooks/mobstack/build-handoff/commerce-release.md) in the applicable build packet. Preserve founder or client intent and keep build and release decisions with the relevant owner.
